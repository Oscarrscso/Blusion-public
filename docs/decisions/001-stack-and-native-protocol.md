# ADR-001 · Stack, and native implementation of the addon protocol

- **Status:** accepted · **Date:** 2026-10-07 · **Node:** M0

## Context

Blusion is an iPhone-first, iPad-compatible player that works with Stremio-style addons
(manifest URL, catalogs, metadata, streams, subtitles). PLAN.md §1 fixes the constraints:
Swift 6 language mode, SwiftUI + Observation, `NavigationStack`, async/await, no Combine, no storyboards,
XcodeGen for the project, Swift Testing for unit tests and XCUITest for UI tests.

## Decision

1. **Stack:** Swift 6 (language mode 6, complete strict concurrency), SwiftUI, `@Observable`, iOS 17+.
   The project is generated by XcodeGen from `project.yml`; `.xcodeproj` is never committed or hand-edited.
2. **Native protocol implementation** in `StremioKit` (Foundation-only), not `stremio-core` via FFI.
   Reasons:
   - The wire protocol is small: one manifest document, five GET resources, JSON responses (PLAN §4).
   - `stremio-core` is a Rust crate designed around its own runtime, storage and account model. An FFI bridge would add a
     Rust toolchain, a generated bindings layer and a binary artifact to every build, for features the app does not use
     (account sync, library sync, the torrent-adjacent runtime).
   - A Foundation-only Swift package builds and tests on any host (macOS and Linux), which is what makes the
     host-side `swift test` gate in PLAN §3 possible, including on this Linux agent host (ADR-002).
   - Lenient decoding, secret redaction and per-addon error isolation are product requirements that are easier to guarantee
     in code we own.
3. **Revisit trigger (from PLAN §1):** only if M1 shows the protocol is materially more complex than PLAN §4 says.
   M1 outcome is recorded in ADR-003.

## Consequences

- We own conformance. The mitigation is fixture-driven tests (≥10 manifest variants), mutation tests that must never crash the decoder,
  and the local mock addon.
- Protocol additions are cheap (new optional fields on lenient models) and never break installed addons.
- No Rust, no FFI, no extra binary dependency in the base app. The only planned binary dependency is the single
  fallback player of M6 (ADR required, pre-approved by PLAN §1).
